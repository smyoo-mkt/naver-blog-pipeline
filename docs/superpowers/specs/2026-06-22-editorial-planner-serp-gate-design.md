# 네이버 파이프라인 확장 설계 2차: 에디토리얼 플래너 + SERP 분석 + 감수 양식

작성일: 2026-06-22
대상: `naver-blog-pipeline` (세무기장 전환 전용)
선행: 2026-06-22 키워드 큐레이터 + 콘텐츠 리프레시 (완료)

## 배경 / 문제

큐레이터·리프레시로 파이프라인 앞뒤 축이 생겼다. 남은 3개 빈틈:

1. **블로그 단위 구조가 없다** — 라이터가 `[내부링크: ...]`를 비워두는데 어떤 글과 연결할지 아는 주체가 없고, 시즈널 발행 일정(가이드 5-③)을 사람이 머릿속으로만 관리한다. C-Rank는 클러스터·내부링크·지속성을 본다.
2. **차별화 각도가 약하다** — D.I.A.+의 핵심은 독창성인데, 브리프 단계에 "네이버 상위 글 분석 → 빈틈 찾기"가 책임으로 박혀 있지 않다.
3. **감수 게이트가 자유서술** — 게이트2에서 세무사가 ①사실 ②사례 삽입 ③과장 제거를 하는데 입력 양식이 없어 누락·지연 위험.

## 목표

- 신규 에이전트 1개 `naver-editorial-planner`(블로그 단위 발행 캘린더 + 내부링크 그래프).
- 기존 `naver-brief-planner`에 SERP 경쟁 분석 단계 추가.
- 기존 `naver-seo-editor` 산출물에 세무사 감수 기입란 템플릿 추가 + 내부링크 검증 강화.

## 비목표

- 검색량 API 연동(추정·수기 유지).
- 내부링크 자동 삽입(에이전트가 초안을 직접 수정하지 않음 — 제안만).
- 새 슬래시 커맨드.

---

## 1. 에이전트: `naver-editorial-planner` (블로그 단위 구조)

- **frontmatter tools:** Read, Write (웹 조사 불필요)
- **작업 전 읽기:** `work/content-registry.md`, 기존 `work/*-draft.md`/`*-review.md`(발행물), `guides/naver-seo-guide.md`(시즈널 캘린더·C-Rank 지속성)
- **할 일 (출력 파일 1개 `work/editorial-plan.md`, 두 섹션):**
  1. **발행 캘린더** — registry의 `season`·`status=후보/기획` 행 + 시즈널 캘린더를 읽어 키워드를 월/주차에 배치. 신고철 2~3주 전 역산. 주 3~5회 리듬(C-Rank 지속성) 고려한 발행 순서 제안.
  2. **내부링크 그래프** — registry `cluster`별로 발행물을 묶어 필러↔서브 링크 관계 제안. 특정 초안의 `[내부링크: ...]` 자리에 넣을 구체적 slug/제목 추천.
- **핸드오프:** 초안을 직접 수정하지 않는다. 제안 파일만 낸다. 라이터/에디터가 참고해 placeholder를 채운다.

## 2. `naver-brief-planner` 보강 — SERP 경쟁 분석

- 기존 도구(WebSearch, WebFetch) 사용. 새 도구 없음.
- **할 일에 1단계 추가:** 타겟 키워드를 WebSearch해 네이버 상위 글을 분석 → 공통 소재 / **빠진 각도(차별화 지점)** 도출. 이를 기존 "각도" 항목에 반영.
- **출력에 섹션 추가:** `경쟁 글 분석 + 차별화 각도` (상위 글 요지 + 우리가 다르게 갈 지점).
- 기존 게이트1(브리프 승인) 문구·registry 연동은 그대로 유지.

## 3. `naver-seo-editor` 보강 — 감수 양식 + 내부링크 검증

- **체크리스트 강화:** 기존 "내부링크 자리 존재" 항목을 *"`work/editorial-plan.md`의 클러스터 관계대로 내부링크가 채워졌는가"* 로 교체. (editorial-plan이 없으면 자리 존재만 확인)
- **review.md에 세무사 기입란 템플릿 자동 첨부:**
  1. 사실 정확성: 핵심 사실 항목별 `[ ] OK / 수정:____`
  2. `[세무사 사례 삽입]` → 실제 사례 입력 칸(빈칸)
  3. 과장표현 점검: `[ ] 절세 보장·과장 없음 확인`
  4. 최종 발행 승인: 세무사명·날짜 서명란
- 기존 게이트2 핸드오프 문구는 그대로 유지(이 양식이 그 게이트의 작업 도구).

## 4. 통합

- `README.md`: 구조도 7개 에이전트(editorial-planner 추가), `work/`에 `editorial-plan.md` 추가. 흐름도에 editorial-planner를 앞단(캘린더)·작성단(내부링크 참고) 위치로 표기.

## 성공 기준 (검증)

- `.claude/agents/naver-editorial-planner.md`가 frontmatter(name/description/tools: Read, Write) + 두 섹션 출력 책임으로 존재한다.
- `naver-brief-planner.md`에 SERP 분석 할 일 단계 + 차별화 각도 출력 섹션이 있다(기존 registry 연동·게이트1 문구 유지).
- `naver-seo-editor.md`의 내부링크 체크가 editorial-plan 기준으로 강화되고, review.md에 세무사 기입란 4종(사실/사례/과장/서명)을 첨부하는 작업이 명시된다(기존 게이트2 문구 유지).
